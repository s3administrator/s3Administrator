# S3 Administrator — Agent Documentation

Internal reference for AI agents and developers working on this codebase.

---

## What Is This?

S3 Administrator is an open-source S3 file manager with two editions:

- **Community** — Self-hosted, single-user, all features unlocked, no auth/billing
- **Cloud** — Multi-user SaaS with OAuth, Stripe billing, audit logs, admin panel

Both editions share the same codebase. The edition is controlled by two env vars:

| Var | Community | Cloud |
|-----|-----------|-------|
| `ENVIRONMENT` | `COMMUNITY` | `CLOUD` |
| `NEXT_PUBLIC_EDITION` | `community` | `cloud` |

Cloud-only features live in 5 **private** `@s3administrator/*` packages (auth, billing, admin, audit, marketing). Community builds without them — stub files are generated by `@s3administrator/community-setup`.

---

## Tech Stack

- **Next.js 16** (App Router) + **React 19** + **TypeScript**
- **Prisma 6** — Do NOT upgrade to Prisma 7 (Turbopack incompatibility)
- **Auth.js v5** (`next-auth@beta`) with database sessions
- **shadcn/ui** + **Tailwind CSS v4**
- **@aws-sdk/client-s3** for all S3 providers
- **Stripe** for billing, **Resend** for emails
- **PostgreSQL** for database

## Environment Variable Resolution

`envVar("STRIPE_SECRET_KEY")` looks up in this order:

1. `STRIPE_SECRET_KEY_CLOUD` or `STRIPE_SECRET_KEY_COMMUNITY` (based on `ENVIRONMENT`)
2. `STRIPE_SECRET_KEY` (unsuffixed fallback)

Prefer unsuffixed keys for simplicity. Only use suffixed keys when community and cloud need different values.

## Two-Edition Stub System

Cloud features are provided by 5 private packages: `@s3administrator/{auth,billing,admin,audit,marketing}`.

**How it works:**

1. `npm install` runs `postinstall`
2. If `@s3administrator/community-setup` is installed → generates community fallback stubs (redirects, 404 routes, no-op libs)
3. If `@s3administrator/setup` is installed → overwrites with real cloud re-exports
4. Generated files have `// @generated by s3admin` header — never edit these manually

**Stub types:**

| Type | Generated content |
|------|-------------------|
| `lib-critical` | Working implementation (entitlements, audit logger, etc.) |
| `lib-empty` | `export {}` — unused in community |
| `page` | `redirect("/dashboard")` |
| `layout` | Passthrough `<>{children}</>` |
| `route` | Returns 404 "Not available in community edition" |
| `skip` | Never generated (e.g., login page is real community code) |

The registry of all 56 stub paths lives in `packages/community-setup/src/registry.ts`.

## Best Practices

### General

- **Read before editing.** Understand existing code before modifying. Check imports, callers, and tests.
- **Prefer editing over creating.** Don't create new files unless necessary. Build on what exists.
- **Keep it simple.** Don't add abstractions for one-time operations. Three similar lines > premature helper function.
- **No over-engineering.** Only implement what's requested. Don't add error handling for impossible scenarios.

### Edition-Aware Code

- Use `isCommunityEdition()` / `isCloudEdition()` from `src/lib/edition.ts` for conditional rendering.
- Never hard-import from `@s3administrator/*` packages directly — use `plugin-registry.ts` to check availability first, then dynamic `import()`.
- Stub files are auto-generated. Edit the stub content in `packages/community-setup/src/stubs/` if community behavior needs changing, then republish.

### Database

- **Prisma 6 only.** Prisma 7 has breaking changes with Turbopack. Don't upgrade.
- Always run `npx prisma migrate dev --name descriptive-name` for schema changes.
- Seed script at `prisma/seed.ts` — keep it idempotent (upserts, not creates).

### API Routes

- All S3 routes check auth via `src/lib/api-guard.ts`.
- Rate limiting is per-user via `src/lib/rate-limit.ts`.
- Feature gates checked via `plan-entitlements.ts` and `plan-limits.ts`.
- Validate all input with Zod schemas from `src/lib/validations.ts`.

### Security

- S3 credentials are encrypted at rest with AES-256-GCM (`src/lib/crypto.ts`).
- Never log decrypted keys. Never return them in API responses.
- Auth.js uses database sessions (not JWT).
- Build-time initialization of Stripe/Resend will fail if keys are empty — use lazy initialization patterns.

### Styling

- shadcn/ui components in `src/components/ui/`. Button sizes: `sm`, `default`, `lg`, `icon`.
- Tailwind CSS v4 — no `tailwind.config.js`, configuration is in `globals.css`.
- Import `cn()` from `src/lib/utils.ts` for conditional classes.

### Publishing community-setup

```bash
cd packages/community-setup
# bump version in package.json
npm publish --registry https://npm.pkg.github.com
```

The package is also mirrored at `github.com/s3administrator/community-setup`.

## Docker Architecture

- `deps` — Install node_modules (with NPM_TOKEN for private packages)
- `builder` — Build Next.js standalone
- `tools` — Prisma CLI for migrations/seed

- `app` — Next.js on port 3000
- `db` — PostgreSQL 16 on port 5433
- `proxy` — Caddy reverse proxy on 80/443
- `node-exporter` — Prometheus metrics on 9100
- `tools` — Prisma CLI (run-once)

## Common Pitfalls

| Pitfall | Solution |
|---------|----------|
| Build fails with empty Stripe/Resend keys | Use lazy initialization (function/proxy), not top-level `new Client()` |
| Prisma client not found | Run `npx prisma generate` after install |
| OAuth buttons don't work | Check env vars are unsuffixed or match the `ENVIRONMENT` suffix |
| `@s3administrator/*` import errors | Community stubs not generated — run `npx s3admin-community-setup` |
| TypeScript errors in `packages/` | Already excluded in `tsconfig.json` — don't remove `"packages"` from `exclude` |
| Stripe API version mismatch | SDK version must match API version (e.g., stripe@20.x = `2026-01-28.clover`) |
| Zod v4 import | Use `from "zod/v4"`, not `from "zod"` |
